# Verification security review APIs (#950–953)

All protected endpoints require Authorization: Bearer ADMIN_TOKEN. Missing configuration disables access. x-user-id and caller supplied roles confer no private access. The current authentication system has public and operator roles only; private owner access needs a future authenticated identity provider.

## Advisory risk
GET /admin/risk/:creator reads persisted verification outcomes, not HTTP errors or worker retries. Distinct jobIds count once. Only current failed outcomes updated inside the rolling window count; successful recovery removes that record from the failure count. Defaults: RISK_WINDOW_MS=3600000, RISK_MINIMUM_FAILURES=3, RISK_POINTS_PER_FAILURE=10, RISK_REVIEW_SCORE=50. Below the minimum the score is zero; otherwise min(100, failures × points). Values are positive integers. Response includes counts, window, evaluation time and effective rules. This signal never denies verification, recovery or downloads. Operators must investigate infrastructure outages and user context before taking action. It is a current-state signal, not a historical attempt ledger.

## Masking contract
Verification, certificate and creator-list responses use an explicit allowlist and visibility: public/private. Public responses contain jobId, status, certificate/transaction identifiers and lifecycle timestamps. Only explicit sharingPolicy=public exposes contentHash, manifestHash and creator. Missing policy defaults private. Operators additionally receive these fields, raw error and manifest. Arbitrary nested manifest fields are omitted entirely from public responses. storageRef and database identifiers never appear in these responses. Cached documents are masked after lookup without mutation. Existing clients must tolerate withheld fields and the visibility discriminator.

## Audit export
POST /admin/audit-exports/:jobId returns payload and integrity. Payload includes the complete stored verification, its source database/collection/network, lifecycle timestamps, requesting credential class, export UUID/time, and security audit history. Read semantics are explicitly recorded; this is not an atomic snapshot across collections. A separate receipt and audit event are persisted before return. Export access is operator-only because the payload includes private provenance.

To independently verify, canonicalize payload recursively: sort object keys lexicographically, preserve array order, encode JSON scalars with JSON.stringify, and omit whitespace. Hash UTF-8 canonical bytes with SHA-256 and compare integrity.sha256. Compare exportId and digest against the separately retained audit_export_receipts record. A digest packaged with the export alone does not authenticate it against replacement of both payload and digest. Preserve receipts in independent append-only/WORM storage and restrict the runtime database principal to insert/find on receipts and audit events (no update/delete). Export files become immutable review artifacts when retained in that storage; application code does not claim to defeat database administrator tampering. Shared admin tokens identify a credential class, not an individual reviewer; use distinct authenticated credentials upstream for individual attribution.

## Temporary evidence
Set MEDIA_STORAGE_DIR and explicitly set evidenceDownloadAllowed=true on a verification through trusted policy management. POST /admin/evidence-links/:jobId returns a relative authenticated download path. Default expiry is 300 seconds; EVIDENCE_DOWNLOAD_TTL_SECONDS is clamped to 1–900. GET /api/evidence/download/:token requires the admin bearer token again; the link alone grants nothing. Every use checks the persisted grant, expiry, current evidence permission and unchanged storage binding. Local paths are confined to the real storage root. Storage directories must be writable only by the trusted storage service to prevent filesystem replacement races.

Links are reusable until expiry or DELETE /admin/evidence-links/:token. Revocation is idempotent and shared across instances through MongoDB. Revocation cannot recall bytes from an already authorized in-flight download. Changing the storage reference or clearing evidenceDownloadAllowed invalidates subsequent use immediately. Only local:// evidence is supported; remote storage URLs are never redirected. Grant tokens are stored hashed and redacted from application request paths; configure reverse proxy access logs to redact these paths too. Responses disable caching. Successful issuance, revocation, export and download access are persisted in security_audit_events; persistence failure fails the operation.

Tests are in backend/test/security-policy.test.ts and backend/test/security-service.test.ts. They were added without executing commands, per the requested workflow.
